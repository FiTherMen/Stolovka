# Столовка

Маркетплейс домашньої їжі: кухарі викладають свої страви, сусіди замовляють сніданок, обід або вечерю з доставкою до дверей, а платформа отримує відсоток.

Один вебзастосунок працює як сайт, як застосунок на телефоні (PWA, «Додати на головний екран») і як Telegram Mini App.

**Демо без бази:** `npm run build:demo` збирає одну сторінку `dist-demo/stolovka-demo.html` з тестовими даними і перемикачем ролей (клієнт / кухар / адмін).

**Де запускати:** нижче описано Cloudflare Pages + Supabase (усе безкоштовно). Для власного сервера з Docker дивіться [DEPLOY.md](DEPLOY.md).

## Що вміє прототип

**Клієнт**
- Меню на 7 днів уперед з вкладками «Сніданок / Обід / Вечеря», фільтр за кухарем, середня оцінка страви, залишок порцій.
- Картка страви: фото (до 3), опис, вага або обʼєм, склад, 14 алергенів ЄС, КБЖУ на порцію, мітки, умови зберігання, відгуки.
- Кошик зі стравами різних кухарів (для кожного кухаря створюється окреме замовлення).
- Оформлення: імʼя, телефон, квартира, доставка до дверей або самовивіз, коментар, згода на обробку даних. Оплата готівкою.
- «Мої замовлення»: статус, скасування до прийняття, «Повторити», оцінка 1–5 і відгук лише для отриманих страв.
- Вхід через Telegram (автоматично в Mini App, кнопкою на сайті) або поштою з паролем.

**Кухар** (`/kitchen`)
- Реєстрація кухаря → заявка чекає схвалення адміністратора.
- Страви: додати, змінити, вимкнути, ліміт порцій на день, вікна, у які страва готується. Кнопка «Тестове меню» додає 10 українських страв.
- Замовлення за днями, підсумок «що готувати», кнопки статусу: Прийняти → Готую → Готово → Видано і оплачено.
- Відгуки з відповіддю, продажі за місяць і відсоток платформи.
- Підключення сповіщень у Telegram однією кнопкою.

**Адміністратор** (`/admin`)
- Схвалення, відхилення, призупинення кухарів.
- Усі замовлення за день, звіт продажів і відсотка платформи по кухарях за місяць.
- Приховування відгуків.
- Налаштування: відсоток платформи, на скільки днів уперед можна замовляти, години видачі і дедлайни замовлення для кожного вікна.

**Telegram-бот**
- Нове замовлення приходить кухарю (і копія адміністраторам) з кнопкою «Відкрити кухню».
- Клієнт отримує підтвердження і повідомлення при кожній зміні статусу, після видачі — прохання оцінити.
- `/start` відкриває меню, кнопка меню бота відкриває Mini App.

### Години вікон (за замовчуванням, змінюються в адмінці)

## Технології

- **React + Vite + TypeScript** — вебзастосунок (`src/`).
- **Supabase** (безкоштовний тариф) — база Postgres, вхід, сховище фото. Схема і правила доступу: `supabase/migrations/0001_init.sql`.
- **Cloudflare Pages** (безкоштовний тариф) — хостинг сайту і серверні функції (`functions/`) для входу через Telegram і сповіщень.
- **Telegram Bot API** — бот і Mini App.

Усі перевірки (дедлайни, ліміти порцій, хто що бачить) працюють у базі через RLS і функції, тому їх не можна обійти з браузера.

## Що потрібно від власника

Нічого з цього не треба надсилати в чат: усі ключі вставляються безпосередньо в налаштування Supabase і Cloudflare.

1. **Telegram-бот.** У [@BotFather](https://t.me/BotFather): `/newbot`, придумати назву і імʼя (напр. `StolovkaBcnBot`). Збережіть токен у менеджері паролів.
2. **Свій Telegram ID** (число). Його покаже бот [@userinfobot](https://t.me/userinfobot). Цей ID стане адміністратором.
3. **Акаунт Supabase** — [supabase.com](https://supabase.com), вхід через GitHub, новий проєкт, регіон `West EU` або `Central EU`.
4. **Акаунт Cloudflare** — [dash.cloudflare.com](https://dash.cloudflare.com), безкоштовний.

## Запуск (≈20 хвилин)

### 1. Supabase

1. Створіть проєкт. Пароль бази збережіть, але в застосунку він не потрібен.
2. **SQL Editor → New query**, вставте весь вміст `supabase/migrations/0001_init.sql`, натисніть **Run**.
3. **Project Settings → API**: знадобляться `Project URL`, ключ `anon public` і ключ `service_role` (секретний!).
4. **Authentication → Sign In / Providers → Email**: для швидкого старту можна вимкнути «Confirm email», інакше вбудована пошта Supabase надсилає лише кілька листів на годину.
5. **Authentication → URL Configuration → Site URL**: адреса сайту з кроку 2 (напр. `https://stolovka.pages.dev`).

### 2. Cloudflare Pages

1. **Workers & Pages → Create → Pages → Connect to Git**, оберіть репозиторій `Stolovka`.
2. Build command: `npm run build`, output directory: `dist`.
3. **Settings → Variables and Secrets**, додайте:

| Змінна | Тип | Значення |
|---|---|---|
| `VITE_SUPABASE_URL` | Text | Project URL з Supabase |
| `VITE_SUPABASE_ANON_KEY` | Text | ключ `anon public` |
| `VITE_TELEGRAM_BOT_USERNAME` | Text | `online_stolovka_bot` |
| `SUPABASE_URL` | Text | той самий Project URL |
| `SUPABASE_ANON_KEY` | Text | ключ `anon public` |
| `SUPABASE_SERVICE_ROLE_KEY` | **Secret** | ключ `service_role` |
| `TELEGRAM_BOT_TOKEN` | **Secret** | токен від BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | **Secret** | будь-який довгий рядок з букв і цифр (придумайте самі) |
| `ADMIN_TELEGRAM_IDS` | Text | ваш Telegram ID; кілька — через кому |
| `PUBLIC_APP_URL` | Text | адреса сайту, напр. `https://stolovka.pages.dev` |

4. **Deployments → Retry deployment**, щоб збірка підхопила змінні.

### 3. Telegram

1. Один раз відкрийте в браузері `https://<ваш-сайт>/api/telegram/setup?secret=<TELEGRAM_WEBHOOK_SECRET>`. У відповіді має бути `"ok": true` для webhook і menu. Це підключає бота до сайту і ставить кнопку «Меню».
2. У BotFather: `/setdomain` → оберіть бота → вкажіть домен сайту (потрібно для кнопки входу через Telegram на звичайному сайті).
3. Напишіть боту `/start` і відкрийте меню. Ви автоматично станете адміністратором, бо ваш ID є в `ADMIN_TELEGRAM_IDS`.

### 4. Перший кухар

1. У застосунку відкрийте «Кухня» → заповніть анкету.
2. В «Адмінці» схваліть кухаря.
3. «Кухня → Страви → Тестове меню» додасть 10 страв; «Кухня → Профіль → Підключити Telegram» увімкне сповіщення.

Якщо потрібно призначити адміністратора вручну (напр. акаунт з поштою), у Supabase SQL Editor:

```sql
update profiles set role = 'admin'
where id = (select id from auth.users where email = 'you@example.com');
```

## Локальна розробка

`npm run dev` з `VITE_DEMO=1` запускає застосунок на тестових даних без Supabase: `VITE_DEMO=1 npm run dev`.


```bash
npm install
cp .env.example .env.local        # вставте публічні значення Supabase
npm run dev                       # лише фронтенд, http://localhost:5173
```

Щоб разом із серверними функціями: `cp .dev.vars.example .dev.vars`, заповнити, `npm run build && npx wrangler pages dev dist`.

`npm run typecheck` перевіряє типи фронтенду і функцій.

## Відомі обмеження прототипу

- Оплата лише готівкою, підписки немає (за домовленістю відкладено).
- Один будинок: у даних уже є «будинок», але вибору будинку в інтерфейсі поки немає.
- Акаунт з поштою і акаунт Telegram — це два різні акаунти; обʼєднання не зроблено.
- Нагадування «оцініть страву» надсилається одразу після статусу «Видано», а не через 2 години.
- Тексти «Конфіденційність і правила» — чернетка, потребує перевірки gestoría.
- Нативних застосунків для App Store / Google Play немає; PWA встановлюється з браузера.
